# Neutrino context

Use this as a **map**, not a frozen implementation specification. Neutrino is a Go/Cobra CLI with Helm template analysis and a Bubble Tea TUI. It statically inspects Helm charts, Zarf packages, and UDS bundles; it is not a package author, deployer, or template executor. The repository's checked-in bundles are test fixtures, not an authored production bundle. The domain vocabulary and inspection success criterion live in [`CONTEXT.md`](../../../CONTEXT.md): a Bundle Inspection succeeds only when every selected package yields a complete Package View.

## Gather context

1. Read [`CONTEXT.md`](../../../CONTEXT.md) and the [manifest-first Package Reader ADR](../../../docs/adr/0001-manifest-first-package-reader.md). Use their Package Root, Package Snapshot, Package View, and Bundle Inspection terms. **Done when** the change's input format and Package View completeness obligations are identified.
2. Follow the relevant branch below; read its Neutrino code and first-party upstream reference. Consult [`go.mod`](../../../go.mod) for the pinned Zarf API before applying newer Zarf documentation, and read the actual UDS artifact/parser code before applying an older format proposal. **Done when** each configuration input has an owner, precedence, and known/static versus runtime classification.
3. Trace from [`src/cmd/inspect.go`](../../../src/cmd/inspect.go) through [`src/pkg/helm/introspect/`](../../../src/pkg/helm/introspect/) to [`src/pkg/tui/`](../../../src/pkg/tui/) and [`docs/cli-reference.md`](../../../docs/cli-reference.md) when outputs change. **Done when** every affected CLI, report, TUI, test, and documentation surface is accounted for without relabeling an old field as a new kind of value.

## Configuration boundaries

| Owner | Input and meaning | Where to look |
| --- | --- | --- |
| Helm chart | Chart `values.yaml`, chart-level files, and Helm template `.Values`; chart defaults are not Zarf Package Values. | [`introspect.go`](../../../src/pkg/helm/introspect/introspect.go), [`ast-walker.md`](../../../docs/ast-walker.md), [Helm values guide](https://helm.sh/docs/chart_template_guide/values_files/) |
| Zarf legacy variable | Package `variables`, deploy-time/user or `setVariables` input; `###ZARF_VAR_NAME###` substitution and chart `variables[].path` are separate usage surfaces. Neutrino reports declarations and markers, not their deployment result. | [`zarf.go`](../../../src/pkg/helm/introspect/zarf.go), [`util.go`](../../../src/pkg/helm/introspect/util.go), [Zarf Deployment Variables](https://docs.zarf.dev/ref/values/#variables-zarf_var_) |
| Zarf legacy constant | Package `constants` are set by the **package creator** and available through `###ZARF_CONST_NAME###`; they are not deploy-time variables or Zarf Package Values. Treat constants as a distinct upstream concept: inspect current code before claiming Neutrino reports them. | [Zarf Constants](https://docs.zarf.dev/ref/values/#constants-zarf_const_), [`types.go`](../../../src/pkg/helm/introspect/types.go) |
| Zarf Package Values | Structured package `values.files` and optional JSON schema; packaged files, then operator `--values` files in order. Chart `values` mappings use `sourcePath` → `targetPath`, optional `excludePaths`. v1alpha1 `templatedValuesFiles`, v1beta1 ordered `valuesFiles[].enableTemplating`, `.State`, and `setValues` may require deployment context. | [`package_values.go`](../../../src/pkg/helm/introspect/package_values.go), [`zarf.go`](../../../src/pkg/helm/introspect/zarf.go), [Zarf Package Values](https://docs.zarf.dev/ref/package-values/) |
| UDS Legacy | `uds-bundle.yaml` package selection, fixed `overrides.*.*.values`, and configurable `overrides.*.*.variables` via legacy `uds-config.yaml`. An override is neither a chart default nor a Zarf Package Value. | [`uds.go`](../../../src/pkg/helm/introspect/uds.go), [`types.go`](../../../src/pkg/helm/introspect/types.go), [UDS CLI Legacy quickstart](https://github.com/defenseunicorns/uds-cli/blob/main/README.md#legacy-mode-quickstart) |
| UDS Next | `bundle.uds.hcl` package IDs/sources/dependencies and ordered `values_files`; `defaults.uds.hcl` plus optional `config.uds.hcl` supply bundle `.vars` used to render bundle values files. Next bundle config is not Zarf's `.Values` or Helm's `.Values`. | [`next.go`](../../../src/pkg/helm/introspect/next.go), [`next_detect.go`](../../../src/pkg/helm/introspect/next_detect.go), [UDS CLI modes](https://github.com/defenseunicorns/uds-cli/blob/main/README.md#cli-modes), [Bundles Next ADR](https://github.com/defenseunicorns/uds-cli/blob/main/docs/adr/0001-bundles-next-spec.md) |

**Provenance:** Maintain separate package, bundle, and chart configuration identities and ordered inputs. Report mapped paths without presenting the mapping as an applied chart default. Runtime templates/actions and missing deployment inputs stay unresolved. In mixed packages and bundles, retain Legacy variable/override reporting alongside Package Values; see the [Zarf migration guide](https://docs.zarf.dev/best-practices/variables-to-values/) for upstream differences.

## Artifact and reference checks

- Remote direct-Zarf and embedded packages use the [`package_reader.go`](../../../src/pkg/helm/introspect/package_reader.go) Package Reader: resolve the requested platform, verify digest/size, select `zarf.yaml`, needed component/chart content, and packaged `values.yaml`/`values.schema.json`. Preserve the ADR's no-`images/**` transfer and all-or-nothing Package View invariant. Pinned Zarf v0.87.0 supports alpha and beta definitions; [`zarf_definition.go`](../../../src/pkg/helm/introspect/zarf_definition.go) selects the highest supported document without loading resources. Assembled values/schema paths remain distinct from source paths. Empty assembled values omitted by upstream remain an explicit unsupported layout; see package-handling docs.
- Legacy UDS manifests and Next OCI indexes are different formats. Next detection/inspection lives in [`next_detect.go`](../../../src/pkg/helm/introspect/next_detect.go), [`next.go`](../../../src/pkg/helm/introspect/next.go), and [`next_archive.go`](../../../src/pkg/helm/introspect/next_archive.go); use actual format implementations and fixtures rather than assuming the design ADR's illustrative OCI layout is deployed unchanged.
- [`docs/package-handling.md`](../../../docs/package-handling.md) and [`docs/tui.md`](../../../docs/tui.md) describe present surfaces. The dated [UDS Next note](uds-cli-next-bundles-research.md) and [Zarf Values/Next note](uds-next-zarf-values-research.md) are bundled reference material with primary-source links and migration questions, **not current Neutrino capability**: they predate Next and Package Values implementation. The older UDS note's `bundles/core/uds-bundle.yaml` example describes another repository; do not treat it as a Neutrino fixture.

For behavior changes, use the existing [`src/pkg/helm/introspect/`](../../../src/pkg/helm/introspect/) and [`src/test/e2e/`](../../../src/test/e2e/) tests, then exercise the changed `neutrino inspect` path. Validate both Legacy and Next when routing or shared package inspection changes; check local and OCI artifact selection and no image-blob downloads when changing the Package Reader. **Done when** the changed path and its coexistence boundary have observed outcomes, not merely compilation.
